What we changed, and why it's better

A plain-language tour of the chore/cleanup review session. Each card shows how things worked before, how they work now, and why that matters.

Before — the problem After — the fix Why it's better
Safety net

1. The rule-checker that couldn't see

Before The project has a rule: features must not import each other. A tool was supposed to enforce it — but the imports it needed to police were written in a shorthand (@pg/…) the tool couldn't read. It said "all good" every time, even when the rule was actually being broken.
After The tool now understands the shorthand too. We proved it works by planting a fake violation on purpose — the check failed loudly, exactly as it should — then removed the plant. And we fixed the one real violation it had been hiding all along.
Why better A safety net with a hole is worse than no net: it gives false confidence. Now, if anyone breaks the architecture rule again, the build check catches it the same day instead of months later.
Ownership

2. The borrowed recipe moved home

Before The "adopt this design" feature lived in one drawer (iterations) but kept reaching into a different drawer (generation) to grab the instructions it needed. Two parts of the app were tangled together for no good reason.
After The instructions moved into the drawer of the only feature that uses them (features/iterations/adopt-prompt.ts). The one truly generic helper both areas need moved to the shared shelf (shared/lib/fill-template.ts).
Why better When everything a feature needs lives inside it, you can understand it, change it, or delete it without accidentally breaking a different feature.
Hidden landmine

3. The file saved in the wrong alphabet

Before One source file was saved in an unusual text encoding (UTF-16). Git thought it was a binary blob — like an image — so nobody could review its changes, and the build tool would eventually choke on it.
After Converted byte-by-byte to the normal encoding (UTF-8). Git now shows it as 79 readable lines of code like every other file.
Why better Invisible file problems are the worst kind — everything looks fine until the day it mysteriously breaks. This one is now visible, reviewable, and safe.
Timing bug

4. Announcing the news before updating the record

Before When the component list refreshed, the app told everyone "the list changed!" first, and only then updated its lookup table. Anyone who reacted immediately looked things up in the old table.
After Update the table first, announce second. One line moved (in registry.tsx).
Why better Listeners now always see fresh data. This class of "stale read" bug is brutal to debug later because it only happens in a split-second window.
Hanging clients

5. The meeting that never got adjourned

Before The browser listens to a live feed while the AI generates designs, and waits for a final "done" signal. If the AI process failed to even start, that signal was never sent — the browser just sat there listening forever.
After Every failure path now sends "done" too (emitGenerationDone() in both error handlers).
Why better No more stuck loading states after a failed start. Every conversation the server begins, it now also ends.
Performance

6. Saving your document on every keystroke of a drag

Before Dragging a card across the canvas updated its position dozens of times per second — and every single update wrote the entire canvas to browser storage. Like hitting Ctrl+S sixty times a second.
After The app now waits for a quarter-second pause in activity, then saves once. Closing the tab still saves immediately.
Why better Same safety, a tiny fraction of the work. Smoother dragging, especially on big canvases.
Copy-paste debt

7. Three photocopies of the same paragraph

Before The "send request to the AI and handle what comes back" logic was copy-pasted three times in the chat code, and a prompt-building block was copy-pasted four times. Fixing a bug meant remembering to fix it in every copy.
After One shared helper for each (postGenerate(), buildIterationArtifacts()). Dead leftover code — an unused parameter, a 9-line type file, dead props — deleted.
Why better One place to fix, one place to read. The next person changes the behavior once and it's correct everywhere.
Completeness

8. The index that only counted one shelf

Before Design iterations can live in a couple of alternate folders. The page that lists them checked all folders — but the file that lets them render live only checked one. Some iterations showed up in the list but could never actually display.
After Both now scan the same set of folders, and the generated index writes correct relative paths for files that live elsewhere.
Why better What you see in the list is what can actually render. Two parts of the app no longer disagree about reality.
Trust, but verify

9. We fact-checked our own reviewers

Before The AI review agents reported 18 problems. Two of them were flat-out wrong, and one search silently missed a whole folder that exists. Blindly "fixing" the false reports would have broken working code.
After Every claim was verified against the actual code before touching anything: 7 fixed, 2 rejected with evidence, the rest logged as follow-ups in the handoff document.
Why better The changes that landed are all backed by first-hand evidence, not secondhand reports. The rejected findings are documented so nobody "re-fixes" a non-bug later.
The one big thing we found but did NOT build: the Skills catalog window has Add / Update / Remove / Preview buttons that call four server endpoints which — per git history — never existed. Building them properly means running an external CLI and fetching from GitHub on the server, with real security decisions. That's feature work, not cleanup, so it's documented as the top follow-up in .claude/plans/handoff-cleanup-review-2026-07-26.md.
