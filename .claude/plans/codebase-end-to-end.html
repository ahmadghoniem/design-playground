Codebase map · purpose-first

What ships when you open /playground

A local-dev design canvas dropped into a host React app. You drag host components onto an infinite board, ask Claude Code for layout variations, and preview them live — with zero host package.json diff. This page is not an architecture lecture. It answers one question per file: what user outcome does this earn?

10

Cut or deepen — eliminate redundancy

Use this list when hunting shallow modules. Prefer delete / inline over new layers.

Strong candidates to inline or rename

  • useRegistryItems.ts — subscribe wrapper; only consumer is the sidebar.
  • useFocusNode.ts — one fitView call.
  • model-icons.ts — always Claude; no branching left.
  • ComponentPreviewCard name — implies live preview; it’s a text drag row.
  • useStaticScan fetches full tree/tokens but UI only shows a count when empty — either build layers UI or stop fetching unused fields.
  • inline-reference/parts.tsx — relocated monolith; split by component or reunify honestly.
  • useGenerationCoordination.ts re-export of the shared type — drop the re-export if nothing needs the short path.
  • canvas-relations.ts re-export of CanvasRelation — same idea.

Do not “fix” these (already verified)

  • MultiEdit JSONL parsing — Claude’s payload has top-level file_path; parser is correct.
  • Toolbar delete after reload — handleNodesChange still updates knownIterations; persisted onDelete is optional belt-and-braces.
  • LLM component scan — retired on purpose; do not bring it back.
Quick mental model for “where does new code go?”

Features never import other features. Cross-feature wiring lives in app/. Anything two features (or the server) need goes in shared/. Server stays on relative imports — no @pg/ — so bun server/index.ts works alone.

app/ composes · features/* own a vertical · shared/ is the hallway · server/ is the kitchen · no barrels
