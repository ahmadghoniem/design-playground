design-playground · cleanup workbench

How it works — and what to clean up next

A local-dev-only divergence engine: drop it into a host React app, drag the host's real components onto an infinite canvas, and use an agent CLI (Claude Code) to fan out AI layout/style variations. This page maps the runtime, the file tree, the current features, and — for the cleanup pass — the weaknesses and removable redundancy, ending with a recommended next feature.

01 · Runtime flow

One request, from clean URL to agent spawn

There is no second process. A Hono backend is mounted into the host's Vite dev server via a connect middleware (server/vite-plugin.ts), which does two jobs per request:

Clean-URL rewrite vite

Document GETs to /playground and deep links are internally rewritten to /playground.html; the browser URL stays clean. Everything else falls through via next().

API pass-through hono

Only /playground/api/* reaches Hono via getRequestListener(app.fetch). Hono is a catch-all 404, so it must only see API paths.

Agent spawn core

spawnAgent() runs claude with inherited process.env; stream-json is parsed to live "presence" previews; file-watcher emits iteration-added over SSE.

Three streaming conventions coexist (a real source of cognitive load): streamSSE for progressive iterations (generate), streamText for live agent stdout (design-system), and a new Promise<Response> wrapping child close/error for request/response spawns (discover).

03 · What it does today

Shipping features, each grounded in code

Infinite canvas core

React Flow with custom node types (Component live-preview, Iteration iframe, Skeleton, Image, Text, Shape, Frame). Minimap, snap + helper guides, frames, undo/redo, copy/paste, annotation drawing.

app/PlaygroundCanvas.tsx · nodes/* · lib/canvas-*

AI iteration generation core

The heart. Builds a prompt, POSTs /api/generate, spawns the agent, streams progressive iteration-added events so variations pop onto the canvas live. ~10 dedicated prompt kinds.

04 · Weaknesses

What's structurally weak (severity-ranked)
  • highPlaygroundCanvas is still a ~5,480-LOC god-moduleapp/PlaygroundCanvas.tsx

    Batch I only landed 3 of ~9 seams. Paste, chat-submit, drag-to-iterate, and the generation lifecycle all reach into shared parent refs (nodeIdCounterRef, setNodes/screenToFlowPosition closures), so they couldn't be extracted without untangling the ref wiring first. This is the single biggest locality problem in the repo.

    untangle the shared-ref wiring into a small canvas-state context, then resume the seam extractions.

  • highNo convergence memory — the pick evaporateswhole app

    When the builder drags iteration-3 off the canvas and keeps it, nothing records that choice or why. The richest design signal in the app is discarded every time. It's a divergence engine with no memory of what converged.

    an "Accept / Promote" action that writes a tiny decision doc + screenshot, later fed back into the prompt.

  • medOnly the happy path is ever generatedprompts/*.prompt.ts

    Every iteration prompt varies the component as given; none ask for loading, empty, error, disabled, or responsive states. "Design every reachable state" is the cheapest quality upgrade available and it's entirely missing.

    a state axis / Harden mode that fills the missing reachable states, reusing all spawn machinery.

  • medThe best "linter" is trapped in proseskills/make-interfaces-feel-better

    16 mechanically checkable rules (concentric radius, scale(0.96), no transition:all, tabular-nums, 40×40 hit area) only apply if the user opts the skill in, and are never verified after generation.

    promote the deterministic subset into post-generation checks reusing evals/structural-checks.ts; show violations as node badges.

  • medEvals cover one prompt onlyevals/

    The judge + structural-check harness is strong but tests only discovery.prompt.ts. Generation — the actual product — has no quality gate beyond "did it build and register?"

    extend the harness from discovery to generation, with holdouts to test that a skill generalizes vs. memorizes.

  • medenv-inheritance footgunlib/providers/spawn-agent.ts

    The spawned agent inherits the dev server's process.env, so a stale ANTHROPIC_BASE_URL / HTTP(S)_PROXY in the launching terminal silently breaks generation. Only discover.ts sniffs for the connection-refused signature; generate.ts doesn't.

    centralize the connection-refused hint and env sanitization in spawn-agent.ts so every route benefits.

  • lowNo tests, no isolated buildrepo-wide

    Verification is manual ("open /playground and click"). Acceptable for a local-dev throwaway, but it's why refactors lean entirely on git grep gates and human review.

    a minimal node test runner for the pure server/lib/ + lib/ helpers (already extracted to be testable).

  • lowFour overlapping doc systems can driftdocs/ · CLAUDE.md · refactor/

    docs/*.mdc, PROJECT-OVERVIEW.md, AGENT-DESIGN-FRAMEWORK.md, CLAUDE.md, and the refactor/ notes all describe overlapping facts. CLAUDE.md is canonical, but the others can rot independently.

    declare the granular .mdc set the source of truth and reduce the overview docs to generated/linked summaries.

06 · Structural improvements

Where the architecture wants to go next

1 · A canvas-state context unblocks I

The entangled refs (nodeIdCounterRef, getNodeId(), setNodes/screenToFlowPosition) are the only thing keeping paste, chat-submit, and generation-lifecycle inside the god-module. A thin provider exposing them as a stable interface lets the remaining ~6 seams finally extract.

2 · Modernize React Flow usage deferred

Replace the manual frame-bounds Math.min/max with getNodesBounds() and the setNodes(map) dance with updateNode/updateNodeData. Less surface, native semantics.

3 · One streaming helper cohesion

Three streaming idioms is two too many. A small server/lib/agent-stream.ts could own the spawn→stdin→stream→cleanup contract and expose SSE / text / promise modes behind one interface.

4 · Collapse the doc surface clarity

Make docs/*.mdc canonical, generate the overview from it, and keep CLAUDE.md as enforced conventions only. Kills the four-way drift.

07 · Recommended next feature

Accept → decision memory (the keystone)

The throughline: keep the divergence engine exactly as it is, and bolt on the convergence memory it fundamentally lacks — scoped down to a solo, local, throwaway tool.

Today the app generates N takes and the human picks one — and that pick, the single richest design signal in the whole product, is thrown away. Adding memory turns a stateless tool into one that learns this builder's taste.

phase 1 Harden mode

Cheap & on-brand. A state axis that generates the missing reachable states (loading/empty/error/disabled/responsive). Pure prompt work, reuses existing kinds.

phase 2 Accept → exemplar

The keystone. An Accept action writes docs/decisions/{component}-{n}.md (what changed / why it won / screenshot), then feeds accepted exemplars back via a new formatExemplarsSection.

phase 3 Prose → checks

Lift the checkable make-interfaces-feel-better rules into a static checker reusing the structural-checks pattern; surface violations as canvas node badges.

Sequence rationale: phase 1 proves the prompt-axis idea with zero new infra; phase 2 is the actual differentiator (and the highest-value, most on-brand add); phase 3 hardens quality once there's a corpus of accepted exemplars to check against. Full reasoning in docs/AGENT-DESIGN-FRAMEWORK.md.
